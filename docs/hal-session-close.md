# Session-bound action-ledger closure

A completed task may have unavailable pricing. `close_action_ledger` accepts a null cost only when completed work explicitly declares `cost_status=unknown` and a nonempty pricing source. It no longer synthesizes zero from `allow_zero_cost`; a zero requires an explicit value, the true-zero assertion and a pricing source. The client can validate that evidence is present and consistent, not independently verify its truth.

Closure uses the existing ledger ID, session ID and open status as an atomic PATCH filter. It never rewrites session identity. An identical-session repeat can reuse a compatible closed receipt without overwriting its timestamp or accounting. Missing/mismatched sessions fail closed. Kanban requires the latest dispatcher-stamped identity when a run exists, rejects missing stamps instead of falling back to an old task session, and rejects conflicting completion metadata. Task-level fallback is only available when no run exists.

Validation: `scripts/run_tests.sh tests/hermes_cli/test_action_ledger.py tests/hermes_cli/test_hal_fail_closed_complete.py tests/hermes_cli/test_action_ledger_session_close.py -q` passes 30 tests. Eight new regression cases failed on the original fork base; three additional missing-stamp cases failed before the QA follow-up fix. Tests include real HTTP transport to a local ledger fixture and a temporary Kanban database; no production ledger is modified.

This is a partial port of the existing host lifecycle repair onto the SSC fork. Provisional/unbound rows and stale open-row recovery still need the lifecycle reconciler; this patch rejects them instead of silently adopting or retagging them. Artifact completion contracts are not included. Existing runtime code is not replaced by merging this source slice alone. Rollback is a revert of this commit; there is no schema migration.

Deployment gate: the source fork currently stamps worker identity in completion-tool metadata, but does not persist that identity in the attempt before this resolver runs. These boundary tests seed the attempt stamp explicitly; they do not prove dispatcher-to-completion integration. A producer integration and a real worker-path regression are required before merging or deploying this slice.
