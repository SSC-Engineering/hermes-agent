# Session-bound action-ledger closure

A completed task may have unavailable pricing. `close_action_ledger` accepts a null cost only when completed work explicitly declares `cost_status=unknown` and a nonempty pricing source. It no longer synthesizes zero from `allow_zero_cost`; a zero requires an explicit value, the true-zero assertion and a pricing source. The client can validate that evidence is present and consistent, not independently verify its truth.

Closure uses the existing ledger ID, session ID and open status as an atomic PATCH filter. It never rewrites session identity. An identical-session repeat can reuse a compatible closed receipt without overwriting its timestamp or accounting. Missing/mismatched sessions fail closed. Kanban uses persisted attempt identity when a run exists; when missing, it binds the actual runtime session only under a matching dispatcher task/run/profile/claim, otherwise rejects it instead of falling back to an old task session, and rejects conflicting completion metadata. Task-level fallback is only available when no run exists.

Validation: `scripts/run_tests.sh tests/hermes_cli/test_action_ledger.py tests/hermes_cli/test_hal_fail_closed_complete.py tests/hermes_cli/test_action_ledger_session_close.py -q` passes 39 tests. Eight new regression cases failed on the original fork base; three additional missing-stamp cases failed before the QA follow-up fix. Tests include real HTTP transport to a local ledger fixture and a temporary Kanban database; no production ledger is modified.

This is a partial port of the existing host lifecycle repair onto the SSC fork. Provisional/unbound rows and stale open-row recovery still need the lifecycle reconciler; this patch rejects them instead of silently adopting or retagging them. Artifact completion contracts are not included. Existing runtime code is not replaced by merging this source slice alone. Rollback is a revert of this commit; there is no schema migration.

Runtime session binding is verified through the actual completion tool, a temporary Kanban database and real HTTP transport to a local ledger fixture. The current task/run/profile/claim must all match; a compare-and-set write also checks current claim ownership and prior metadata. Completion metadata cannot replace trusted identity. One valid-worker regression failed before the producer fix; stale run, claim, profile and task cases remain rejected.

Fresh claim/open behavior now defers ledger creation until the current worker session is known. The claim hook must not use the task creator's session. Completion late-opens a session-bound row; open-row reuse includes both task and session, preserving earlier or unbound rows. Four regression cases failed before this fix: fresh claims with null/old task-origin identity, and open lookup against unbound/earlier-worker rows. The tests execute actual claim and completion-tool paths with real local HTTP GET/POST/PATCH and no pre-seeded current ledger.

Deployment gate: worker environment is supplied by the isolated test; actual process spawning, accounting during a running/crashed worker, retries with a stale task ledger pointer, and provisional/unbound reconciliation still require verification. Deferring attribution must not be treated as proof of complete lifecycle accounting. This is not a full runtime replacement. Verify those boundaries and CI before merge/deployment.
